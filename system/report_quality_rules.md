# 个人认知雷达报告质量规则

这个文件定义“点子发芽”日报的质量底线。目标不是生成一份资料汇总，而是生成一份个人认知雷达：它要帮助用户判断今天的信息和自己有什么关系、要不要留下、下一步做什么。

## 为什么之前报告质量低

核心问题不是缺少搜索，而是搜索结果的位置太高：

- 先搜索再排版，容易把标题和摘要当作正文。
- 来源分层不清，博客、百科、机构官网和权威媒体在正文里看起来同等重要。
- 旧知识只做关键词匹配，缺少“为什么相关 / 为什么只是弱连接”的解释。
- 没有强制中间层，PDF 直接从输入和搜索结果生成，缺少主线、判断、个人关系和下一步的审稿关口。
- 质量检查偏格式，只能发现缺章节和坏词，不能阻止“看似完整但没有判断”的报告。

## 新的生产原则

日报必须按这个顺序生成：

1. 用户输入是触发器：只使用网页端提交的关键词、上下文、权重。
2. 搜索结果是证据：只用于核实和分层，不直接进入正文。
3. 本地旧知识是镜子：必须扫描 `knowledge/`、`synthesis/idea_seeds/`、`tracking/topics.md`、`library/nodes/`、`library/seeds/`，解释新输入和旧内容的关系。
4. `report_brief.json` 是判断层：先写清主线、每个关键词的个人关联、旧知识连接、来源角色和质量风险。
5. `report.tex` / `report.pdf` 是读者层：只呈现综合判断，不呈现搜索过程。

一句话：先判断，再引用；先和用户发生关系，再说明外部资料。

## 合格报告的标准

- 今日主线是 1-3 句话，有方向感和取舍，不是关键词串。
- 每个关键词卡片都有“它是什么 / 今天查到了什么 / 和我有什么关系 / 今日判断 / 最小下一步”。
- “今天查到了什么”必须是综合改写，不能粘贴搜索标题、搜索摘要或来源列表。
- “和我有什么关系”必须落到用户的学习、项目、申请、实习、人脉、表达、商业观察或系统使用，不写泛泛价值。
- “与旧知识的连接”必须说明为什么相关；弱连接也要解释弱在哪里。
- 点子种子最多 1-3 个，必须来自今日输入、旧知识和可执行下一步的组合。
- 来源必须分层：官方/机构资料 > 论文/报告 > 权威媒体 > 项目主页/机构主页 > 普通线索 > 低优先级线索。
- 低质量来源只能当入口线索，不能当核心结论。
- 明日一问只能有一个，而且必须能引出行动或判断。

## 失败报告的气味

出现下面任一现象，就要重写：

- 正文像搜索结果列表。
- 只解释“它是什么”，没有解释“和我有什么关系”。
- 每个关键词互不相干，没有今日主线。
- 把“暂无强连接”当结论，而不解释为什么弱连接仍然值得或不值得看。
- 来源标题、网页摘要、新闻标题大量进入正文。
- 用“继续关注”“深入研究”“据资料显示”等空话代替判断。
- 无新输入日把泛资讯、股市复盘、工具榜单写成外部新进展。
- 点子种子数量太多，或者没有真实下一步。

## Automation 审稿流程

每日 automation 不能只跑脚本就结束。脚本成功只是第一关。

1. 运行 `python scripts/generate-radar-report.py --date YYYY-MM-DD`。
2. 打开 `synthesis/daily_reports/YYYY-MM-DD/report_brief.json`，确认主线、个人关联、旧知识连接和来源分层都存在。
3. 打开 `quality_check.json`，必须 `passed: true`。
4. 用 `pdftotext` 抽取 `report.pdf`，或直接检查 `report.tex`。
5. 如果读起来像资料汇总、搜索堆砌、百科词条或公司日报，必须修改生成器或 `report.tex` 后重新编译。
6. 只有当 PDF 能回答“今天这些信息和我有什么关系，明天做什么”时，才算完成。
